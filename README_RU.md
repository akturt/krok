# Underboss

**Engineering control plane for projects built with AI coding agents**

Underboss — это система, которая помогает поддерживать проект в актуальном состоянии во время активной разработки.

Она не пытается заменить разработчика, заставить писать идеальную документацию или навязать очередную "правильную" методологию. Ее задача гораздо проще — сделать так, чтобы архитектурные решения, спецификации, знания о проекте и инженерный контекст не превращались в хаос по мере роста проекта.

## Почему появился Underboss

Практически любая система документирования выглядит хорошо до начала настоящей разработки.

Появляются новые требования. Меняются архитектурные решения. Выясняются ограничения. Отбрасываются старые идеи. Возникают новые зависимости. Через несколько недель документация начинает расходиться с реальностью.

В результате:

* архитектура существует только "в голове";
* старые решения забываются;
* невозможно быстро восстановить контекст;
* AI начинает работать по устаревшей информации;
* после длительного перерыва проект приходится практически изучать заново.

Чем сложнее проект, тем сильнее проявляется эта проблема.

Особенно это касается инфраструктурных платформ, IaC, DevOps, DaaS, внутренних платформ и других систем, где одновременно существуют архитектура, инфраструктура, код, процессы эксплуатации и большое количество связанных решений.

## Что делает Underboss

Underboss превращает документацию в рабочую часть процесса разработки.

Он хранит:

* архитектуру;
* ADR;
* спецификации;
* инварианты;
* доменную модель;
* инженерные знания;
* процессы;
* правила для AI-агентов.

Все документы имеют жизненный цикл, проходят проверки и автоматически попадают в правильное место после согласования.

Проект всегда остается в согласованном состоянии.

## Как выглядит работа

Разработка начинается не с большого промпта.

Разработка начинается со спецификации.

Неважно, насколько она хорошая.

Можно написать несколько абзацев обычным языком.

Дальше Underboss:

* приводит документ к каноническому виду;
* размещает его в нужной структуре;
* запускает проверки;
* может вызвать специализированных AI-агентов;
* проводит архитектурное ревью;
* проверяет инварианты;
* запускает adversarial-проверку;
* возвращает документ на доработку при необходимости;
* после утверждения переводит его в реализацию.

После завершения работы документация автоматически становится частью общей базы знаний проекта.

## Почему это важно для AI

Большинство AI coding workflows сегодня строится вокруг огромных `CLAUDE.md`, `AGENTS.md` или системных промптов.

Со временем они становятся все больше.

Они начинают потреблять огромное количество контекста.

При этом большая часть информации агенту вообще не нужна.

Underboss использует другой подход.

AI получает только тот инженерный контекст, который действительно нужен для конкретной задачи.

Без сканирования сотен файлов.

Без устаревшей информации.

Без огромных системных промптов.

* Infrastructure as Code

## Результат

Главная цель Underboss — не написать больше документации.

Главная цель — сделать так, чтобы через полгода проект оставался таким же понятным, как и в день, когда вы начали над ним работать.

Чтобы после длительного перерыва можно было за несколько минут восстановить состояние проекта.

Чтобы AI всегда работал с актуальным инженерным контекстом.

И чтобы документация наконец стала частью разработки, а не ее побочным продуктом.
